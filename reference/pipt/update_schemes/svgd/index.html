    svgd⚓︎

    Stein variational gradient descent (SVGD)

    AdaGrad ⚓︎

    ADAGRAD with a running mean of the squared direction, as in Liu and Wang's code.

    .. math::

    G_k = \rho\, G_{k-1} + (1 - \rho)\, \phi_k^2, \qquad
\Delta_k = \epsilon\, \frac{\phi_k}{\delta + \sqrt{G_k}},

    starting from :math:G_1 = \phi_1^2. Dividing by the typical size of the direction makes a step about :math:\epsilon in every variable, however large its gradient is.

    Parameters:

    Name Type Description Default
    step_size float

    :math:\epsilon.

    		 required
    autocorr float

    :math:\rho, the memory of the squared direction.

    		 0.9

    Attributes:

    Name Type Description
    mean_square ndarray or None

    :math:G_k; None before the first step.

    step(direction, members=None) ⚓︎

    The increment for direction; updates the running mean.

    Adam ⚓︎

    Adam (Kingma and Ba): ADAGRAD's scaling applied to a running mean of the direction.

    .. math::

    m_k = \beta_1 m_{k-1} + (1 - \beta_1)\, \phi_k, \qquad
v_k = \beta_2 v_{k-1} + (1 - \beta_2)\, \phi_k^2, \qquad
\Delta_k = \epsilon\, \frac{\hat m_k}{\delta + \sqrt{\hat v_k}},

    starting from zero, with :math:\hat m_k = m_k / (1 - \beta_1^k) and :math:\hat v_k = v_k / (1 - \beta_2^k) correcting for that start.

    		 0.9
    beta2 float

    Memory of the direction and of its square.

    		 0.9

    DataMisfitWeights ⚓︎

    The adjoint weights :math:w = C_d^{-1} (d_{obs} - g(x)) of one member, from its forward output.

    Handed to the simulator as its adjoint_weights and called there with each member's output, so it is a plain picklable object rather than a closure: parallel runs ship it to their workers. The predictions are read off the output exactly as the ensemble reads them into pred_data, which keeps the weights row for row with the observations.

    EnsemblePrior ⚓︎

    A Gaussian prior known through a sample of it: applies :math:C^{-1} without forming :math:C.

    The sample (nx, n) gives the mean :math:\mu and the anomalies :math:A = (X - \mu 1^\mathsf{T}) / \sqrt{n - 1}, for which :math:C \approx A A^\mathsf{T}. With the singular value decomposition :math:A = U \Sigma V^\mathsf{T},

    .. math::

    \nabla \log p(x) = C^{-1} (\mu - x)
    \approx U \Sigma^{-2} U^\mathsf{T} (\mu - x).

    Only :math:U (nx, rank) and :math:\Sigma are kept. This is the inverse within the directions :math:U the sample describes, at most n - 1 of them; in every other direction the gradient is zero. A sample larger than the state describes them all, and the gradient is then that of the sample covariance.

    Parameters:

    Name Type Description Default
    samples ndarray

    Realisations of the prior, (nx, n).

    		 required
    energy float

    Truncation of the singular values, as in :func:pipt.misc_tools.analysis_tools.truncSVD; 1 keeps them all. Singular values at rounding level are always dropped: they are directions without variance, which cannot be inverted.

    		 1.0

    L: np.ndarray ⚓︎

    The factor :math:L = U \Sigma of :math:C = L L^\mathsf{T}, (nx, rank).

    L_inv: np.ndarray ⚓︎

    Its pseudo-inverse :math:\Sigma^{-1} U^\mathsf{T}, (rank, nx): whitens a deviation from the mean.

    rank: int ⚓︎

    Number of directions the prior term acts in.

    gradient(X) ⚓︎

    :math:\nabla \log p at every column of X, (nx, ne).

    misfit(X) ⚓︎

    :math:(x - \mu)^\mathsf{T} C^{-1} (x - \mu) for every column of X, (ne,).

    Minus twice the log-density up to a constant, so that :meth:gradient is minus half its gradient. Like the gradient it counts only the directions the sample describes.

    GradientDescent ⚓︎

    Plain gradient descent on the Kullback-Leibler divergence, the update of Stordal et al., Eq. 7.

    .. math::

    \Delta_k = \epsilon\, \phi_k

    The step is along :math:\phi_k: the Stein direction already points the way the divergence decreases, which is up the log-posterior and so down the data misfit.

    step_size float

    :math:\epsilon. It multiplies the direction itself, so the right value depends on the size of the gradients.

    		 required

    GraphPrior ⚓︎

    A Gaussian prior known through a sample of it and a graph of its variables: a sparse factor of :math:C^{-1}.

    Where :class:EnsemblePrior takes the covariance of the sample as it is, which has at most n - 1 directions, this prior fits a sparse matrix :math:C_w with :math:C^{-1} \approx C_w^\mathsf{T} C_w to the sample. A row of :math:C_w has entries only for the variables within hops steps of its own in the graph, so the fit has few unknowns per row and gives an inverse covariance of full rank from a sample smaller than the state. The fit is that of EnIF, optimize_sparse_affine_kr_map of graphite-maps, which :func:graphite_maps.precision_estimation.fit_precision_cholesky_approximate calls before it multiplies the factor with its transpose; here the factor itself is kept, because it whitens: :math:C_w (x - \mu) has the identity as covariance.

    Each group of variables is fitted on its own, so the groups are independent in this prior. A variable that does not vary in the sample is left out: it has no prior term and no row in the factor.

    Name Type Description Default
    samples ndarray

    Realisations of the prior, (nx, n).

    		 required
    graphs list

    ((start, stop), graph) for every group of rows of the state, with graph a :class:networkx.Graph on the nodes 0 .. stop - start - 1.

    		 required
    hops int

    Reach of a row of the factor in its graph, EnIF's neighbourhood_expansion.

    		 2

    :math:\mu, (nx, 1).

    The rows of the state that vary in the sample, (rank,).

    LBFGS ⚓︎

    Limited-memory BFGS on the whole ensemble.

    The Stein direction :math:\phi takes the place of minus a gradient, and all members are treated as one long vector :math:z. From the last memory steps the optimizer keeps the pairs

    .. math::

    s_k = z_{k+1} - z_k, \qquad y_k = -(\phi_{k+1} - \phi_k),

    how far the members moved and how much the direction changed. They define an approximation :math:B_k of the inverse Hessian, applied with the usual two-loop recursion, and the quasi-Newton step is

    .. math::

    \Delta_k = B_k\, \phi_k.

    Two things differ from textbook L-BFGS, because :math:\phi is not the gradient of a function the optimizer can evaluate:

    • There is no line search. The step is shortened so that its root-mean-square size never exceeds step_size, and the first step, taken before any pair exists, has exactly that size.
    • A pair can have :math:s_k^\mathsf{T} y_k \le 0, which no positive definite :math:B_k can reproduce. Such pairs are skipped.

    :math:B_k is therefore not the inverse Hessian of anything, and :math:\Delta_k need not point the way the divergence decreases. Nothing checks that it does: the cap on the step is the only safeguard.

    The pairs are 2 * memory arrays of the size of the ensemble, and they are part of the restart checkpoint.

    Parameters:

    Name Type Description Default
    step_size float

    Largest root-mean-square step.

    		 required
    memory int

    Number of pairs kept.

    		 10

    Name Type Description

    SVGD ⚓︎

    Bases: AssimilationScheme

    Stein variational gradient descent with adjoint gradients.

    SVGD moves the members of an ensemble until they sample the posterior. Every member :math:x_i follows the direction that decreases the Kullback-Leibler divergence from the ensemble to the posterior the fastest (Stordal et al., Eq. 7):

    .. math::

    \phi(x_i) = \frac{1}{N} \sum_{j=1}^N \left[ K(x_j, x_i)\,
    \nabla_{x_j} \log p(x_j \mid y) + \nabla_{x_j} K(x_j, x_i) \right].

    The first term is a kernel-weighted average of the members' gradients and pulls the members towards high posterior density. The second term is a repulsion that keeps them apart, so that they spread over the posterior instead of collapsing onto its maximum.

    One iteration (:meth:update_step):

    1. Scale. Express the members in prior standard deviations, :math:z = x / s. Distances, repulsion and step are all taken in :math:z, so a joint state of, say, log-permeability and porosity is not measured in whichever has the larger numbers, and step_size means the same for every variable.
    2. Gradient. Add the two terms of :math:\nabla \log p(x_j \mid y) (Stordal et al., Eq. 10). The data term is the simulator's adjoint :math:H^\mathsf{T} w, with :math:w = C_d^{-1} (d_{obs} - g(x_j)). The scheme hands the simulator these weights through its adjoint_weights (:class:DataMisfitWeights), and the gradient comes back with the forecast: one forward and one adjoint run per member per iteration. The prior term is :math:C_x^{-1}(\mu - x_j), from a large sample of the prior (:class:EnsemblePrior).
    3. Kernel. Fit :math:K(x, x') = \exp(-(d(x, x')/\sigma)^p) to the members' current distances :math:d (:func:fit_kernel); with kernel = 'imq' the inverse multiquadric :math:K = (1 + d^2/\sigma^2)^{-1/2} instead, and with kernel = 'p-imq' its p-variant :math:K = (1 + (d/\sigma)^p)^{-1/2}.
    4. Direction. Compute :math:\phi for every member (:func:stein_direction).
    5. Step. Move the members along :math:\phi with the chosen optimizer, clip them to the prior limits, and forecast.

    Every iteration is written to the log in detail: the misfits and the spread of the members, the two terms of the gradient, the kernel that was fitted, the attraction and the repulsion of the Stein direction, and the step. The log starts with the problem and the options, and ends with a summary of the run.

    The prior mean :math:\mu and covariance :math:C_x are those of a large sample of the prior, prior_cov_samples realisations that are never simulated. :math:C_x is not formed: its inverse is applied through the singular value decomposition of the sample's anomalies. The sample describes at most prior_cov_samples - 1 directions of the state, and the smallest of them may be truncated (prior_cov_energy). In the remaining directions the prior term is zero: nothing pulls the members back there apart from the repulsion and the prior limits. A sample larger than the state leaves no such direction.

    Notes

    Configured through the svgd block of keys_da:

    maxiter Largest number of iterations, default 50. SVGD takes them all unless stein_tol stops it first. kernel 'p-kernel' (default): :math:p and :math:\sigma are refitted every iteration so that the kernel is :math:1 - \alpha at the :math:\alpha-percentile of the members' distances and :math:\alpha at the :math:(1 - \alpha)-percentile (Stordal et al., Eqs. 24-25). 'gaussian': :math:p = 2 and :math:\sigma follows the median rule of Liu and Wang, :math:\sigma^2 = \mathrm{med}(d)^2 / \log N. 'imq': the inverse multiquadric :math:K = (1 + d^2/\sigma^2)^{-1/2} (Gorham and Mackey), which falls off slowly with distance and is positive definite in any dimension; :math:\sigma is refitted every iteration so that the kernel is imq_level at the median distance, by default :math:1/\sqrt{N}, which is :math:\sigma^2 = \mathrm{med}(d)^2 / (N - 1). 'p-imq': the p-variant of the inverse multiquadric, :math:K = (1 + (d/\sigma)^p)^{-1/2}, with :math:p and :math:\sigma refitted every iteration to the same two percentiles as the p-kernel. It has the p-kernel's values at those two distances and the slow fall-off of the inverse multiquadric beyond them; like the p-kernel it is positive definite only for :math:p \le 2. alpha Percentile level the p-kernel and 'p-imq' are fitted to, default 0.05, the value of the paper's illustration of the kernel (its Fig. 1); the history matching example does not state one. imq_level 'imq' only: the value of the kernel for two members at the median distance from each other, between 0 and 1. It is the weight such a member's gradient gets in the other's direction. A high value makes the members share their gradients and keeps them spread; a low value lets every member follow its own gradient, and the ensemble narrows. The default is :math:1/\sqrt{N} for :math:N members: the gradients of the other members then weigh as much as a member's own when they point in unrelated directions, since :math:N such vectors add up to :math:\sqrt{N} times one of them. (The median rule of the Gaussian kernel gives :math:1/N, the balance for gradients that all point the same way.) Where the members are about equally far apart, as in many dimensions, the repulsion is then close to that of the Gaussian kernel for some 20 to 200 members. optimizer How the direction becomes a step: 'adagrad' (default, :class:AdaGrad), 'adam' (:class:Adam), 'gd' (:class:GradientDescent) or 'lbfgs' (:class:LBFGS). step_size Step size of the optimizer, default 0.1. With 'adagrad' and 'adam' a step is about step_size prior standard deviations in every variable. With 'gd' it multiplies the direction itself, so the right value depends on the size of the gradients. With 'lbfgs' it is the largest root-mean-square step, in prior standard deviations. autocorr 'adagrad' only: memory of the squared direction, default 0.9. beta1, beta2 'adam' only: memory of the direction and of its square, defaults 0.9 and 0.999. memory 'lbfgs' only: number of earlier steps the curvature is estimated from, default 10. stein_tol Stop when the root-mean-square size of the Stein direction is below stein_tol times its size in the first iteration, default 0.001. The direction is zero where SVGD has converged: it is what moves the members. On a linear-Gaussian problem with a known posterior the spread of the members is within 1% of the posterior's at 0.001 and within 3 to 15% at 0.01. An optimizer with a fixed step, such as ADAGRAD, may never get that low; the run then takes its maxiter iterations. 0 switches the criterion off. stein_change A second condition for that stop, not used by default. When given, the run stops only when the size of the Stein direction is below stein_tol of its first size and has also changed by less than stein_change of itself since the iteration before: the direction is small and has stopped changing. A run whose direction still falls by more than that in every iteration goes on, also below stein_tol. prior_cov_samples Number of prior realisations the prior mean and covariance are estimated from. They are drawn from the prior_<name> blocks, default 1000; with importstate they are the first prior_cov_samples realisations of that file, default all of them (the members are its first ne). 0 switches the prior term off. prior_cov_energy Truncation of the sample's singular values, as energy elsewhere: a fraction, or a percentage when greater than 1. Default 1: keep every direction the sample describes. prior_cov_estimate 'sample' (default): the covariance of the sample (:class:EnsemblePrior). 'graph': a sparse factor of the inverse covariance fitted to the sample on the graphs of the state (:class:GraphPrior), which has every variable that varies in the sample. The graphs and their reach are those of EnIF, parameter_graphs and neighbourhood_expansion of the enif options, or nearest neighbours from the grid of a prior_<name> block. prior_cov_energy is not used with it.

    The defaults -- ADAGRAD with step size 0.1 and memory 0.9, 50 iterations, a prior of 1000 realisations -- are the settings of the paper's history-matching example.

    Examples:

    >>> result = SVGD.assimilate(keys_da, keys_en, jutul_darcy(keys_sim))
>>> result.nit
50

    stein_stop(size) ⚓︎

    The report that ends the run when the Stein direction has become small, else None.

    size is the size of the direction of the members as they are now. It is compared with the size in the first iteration; the ratio is kept in stein_ratio.     fit_kernel(D, kernel='p-kernel', alpha=0.05, level=None) ⚓︎

    The kernel's (p, sigma) for the members' distances D.

    The p-kernel is fitted so that :math:K = 1 - \alpha at the :math:\alpha-percentile of the distances and :math:K = \alpha at the :math:(1 - \alpha)-percentile (Stordal et al., Eq. 25); the Gaussian kernel has :math:p = 2 and the median rule. Only distinct pairs count: a member replaced by a copy of another adds a zero that says nothing about the spread.

    The inverse multiquadric :math:K = (1 + d^2/\sigma^2)^{-1/2} (kernel = 'imq') has no :math:p: None is returned in its place, which is how :func:stein_direction knows the kernel. Its :math:\sigma makes the kernel level at the median distance :math:m, :math:\sigma = m\,\mathrm{level} / \sqrt{1 - \mathrm{level}^2}. Without a level it is :math:1/\sqrt{n} for :math:n members, so :math:\sigma = m / \sqrt{n - 1}.

    The p-variant of the inverse multiquadric, :math:K = (1 + (d/\sigma)^p)^{-1/2} (kernel = 'p-imq'), is fitted as the p-kernel is, to :math:K = 1 - \alpha at the :math:\alpha-percentile :math:d_{lo} of the distances and :math:K = \alpha at the :math:(1 - \alpha)-percentile :math:d_{hi}. The two conditions are :math:(d_{lo}/\sigma)^p = (1 - \alpha)^{-2} - 1 and :math:(d_{hi}/\sigma)^p = \alpha^{-2} - 1, so

    .. math::

    p = \frac{\log\big((\alpha^{-2} - 1) / ((1 - \alpha)^{-2} - 1)\big)}{\log(d_{hi}/d_{lo})},
\qquad \sigma = d_{hi}\,(\alpha^{-2} - 1)^{-1/p} .

    For the same distances this :math:p is a fixed multiple of the p-kernel's, 2.02 for :math:\alpha = 0.05. :func:stein_direction has to be told that the pair belongs to this kernel (its kernel).

    make_optimizer(options) ⚓︎

    The optimizer the svgd options ask for; ADAGRAD unless optimizer names another.

    Every optimizer reads step_size; autocorr belongs to 'adagrad', beta1 and beta2 to 'adam', and memory to 'lbfgs'.
